# 3일차 프로젝트 뜯어보기

## 1. 프로젝트 구조를 공부하는 이유

FastAPI 프로젝트는 파일을 아무 곳에나 작성하지 않고, 역할별로 폴더를 나누어 관리한다.  
프로젝트가 작을 때는 한 파일에 모두 작성할 수도 있지만, 기능이 늘어나면 코드가 복잡해지기 때문에 아래와 같이 역할을 나누는 것이 좋다.

- `apis`: 사용자의 요청을 받는 곳
- `schemas`: 요청과 응답 데이터의 모양을 정하는 곳
- `services`: 실제 기능과 비즈니스 로직을 처리하는 곳
- `repositories`: 데이터베이스에 접근하는 곳
- `models`: 데이터베이스 테이블 구조를 코드로 표현하는 곳
- `core`: 프로젝트 전체 설정과 공통 기능을 관리하는 곳

쉽게 말하면, FastAPI 프로젝트는 다음 흐름으로 동작한다.

```text
사용자 요청
→ API
→ Schema로 데이터 검사
→ Service에서 기능 처리
→ Repository에서 DB 조회/저장
→ Model을 기준으로 DB 테이블과 연결
→ 사용자에게 응답
```

## 2. 각 디렉터리의 역할

### 2.1 `app/core/`

`app/core/`는 프로젝트 전체에서 공통으로 사용하는 설정과 핵심 기능을 모아두는 폴더이다.

이 프로젝트에서는 다음과 같은 파일이 들어 있다.

```text
app/core/config.py
app/core/db/databases.py
app/core/db/models.py
```

작성해야 하는 내용은 다음과 같다.

- 환경 변수 설정
- 데이터베이스 접속 정보 관리
- 데이터베이스 세션 생성
- 공통 모델 클래스 관리
- 인증, 보안, 공통 예외 처리 같은 프로젝트 핵심 기능

예를 들어 데이터베이스 아이디, 비밀번호, 호스트 주소처럼 여러 파일에서 함께 쓰는 값은 `core`에서 관리한다.

### 2.2 `app/models/`

`app/models/`는 데이터베이스 테이블 구조를 Python 코드로 작성하는 폴더이다.

예를 들어 회원 정보를 저장하는 `users` 테이블이 필요하다면, `User` 모델 클래스를 만들 수 있다.

```python
class User(Base):
    __tablename__ = "users"

    id = mapped_column(Integer, primary_key=True)
    email = mapped_column(String(30), unique=True)
    name = mapped_column(String(10))
```

쉽게 말하면 `models`는 데이터베이스의 설계도이다.

작성해야 하는 내용은 다음과 같다.

- 테이블 이름
- 컬럼 이름
- 컬럼 타입
- 기본키
- 외래키
- unique, nullable 같은 제약 조건

### 2.3 `app/repositories/`

`app/repositories/`는 데이터베이스와 직접 대화하는 코드를 작성하는 폴더이다.

예를 들어 회원을 조회하거나 저장하는 기능은 repository에 작성한다.

```text
회원 목록 조회
회원 1명 조회
회원 저장
회원 수정
회원 삭제
```

쉽게 말하면 `repositories`는 데이터베이스 담당자이다.  
API나 service가 직접 SQL을 작성하지 않도록 중간에서 DB 작업을 담당한다.

작성해야 하는 내용은 다음과 같다.

- DB 조회 함수
- DB 생성 함수
- DB 수정 함수
- DB 삭제 함수
- 조건 검색 함수

### 2.4 `app/schemas/`

`app/schemas/`는 API로 들어오는 요청 데이터와 응답 데이터의 모양을 정하는 폴더이다.

FastAPI에서는 주로 Pydantic 모델을 사용한다.

예를 들어 회원 생성 요청은 다음과 같이 정할 수 있다.

```python
class UserCreate(BaseModel):
    name: str
    age: int
    email: str
    password: str
```

쉽게 말하면 `schemas`는 데이터 검사표이다.

작성해야 하는 내용은 다음과 같다.

- Request Body 형식
- Response Body 형식
- 필수값 여부
- 문자열 길이 제한
- 숫자 범위 제한
- 이메일 형식 검증

### 2.5 `app/services/`

`app/services/`는 실제 기능의 규칙을 처리하는 폴더이다.

예를 들어 회원가입 기능이라면 다음과 같은 규칙을 service에서 처리할 수 있다.

```text
이메일 중복 확인
비밀번호 규칙 확인
회원 생성 처리
필요한 repository 함수 호출
```

쉽게 말하면 `services`는 실제 일을 판단하고 처리하는 곳이다.

작성해야 하는 내용은 다음과 같다.

- 비즈니스 로직
- 여러 repository 함수 조합
- 예외 상황 처리
- API에 바로 넣기에는 긴 기능 처리

### 2.6 `app/apis/`

`app/apis/`는 사용자의 요청을 직접 받는 API Router를 작성하는 폴더이다.

예를 들어 다음과 같은 주소를 만든다.

```text
GET /users
POST /users
PATCH /users/{user_id}
DELETE /users/{user_id}
```

쉽게 말하면 `apis`는 사용자가 들어오는 문이다.

작성해야 하는 내용은 다음과 같다.

- API endpoint
- HTTP method
- path parameter
- query parameter
- request body
- response
- service 함수 호출

## 3. 주요 파일의 역할

### 3.1 `app/main.py`

`app/main.py`는 FastAPI 애플리케이션이 시작되는 파일이다.

이 프로젝트의 `main.py`는 다음 역할을 한다.

- `FastAPI()` 객체 생성
- API router 등록
- `/static` 경로로 정적 파일 제공
- `/media` 경로로 업로드 파일 제공
- `/healthcheck` API 제공
- `/` 접속 시 `static/index.html` 반환

현재 프로젝트에서는 다음 코드로 FastAPI 앱을 만든다.

```python
app = FastAPI()
```

그리고 router를 등록하면 별도 파일에 작성한 API를 서버에 연결할 수 있다.

```python
app.include_router(practice_router)
```

쉽게 말하면 `main.py`는 프로젝트의 전원 버튼이자 입구이다.

### 3.2 `app/core/config.py`

`app/core/config.py`는 프로젝트 설정값을 관리하는 파일이다.

현재 프로젝트에서는 `pydantic-settings`의 `BaseSettings`를 사용하여 데이터베이스 설정을 관리한다.

관리하는 값은 다음과 같다.

```text
DB_USER
DB_PASSWORD
DB_HOST
DB_PORT
DB_NAME
```

또한 `.env` 파일을 읽도록 설정되어 있다.

```python
model_config = {
    "env_file": ".env",
    "extra": "ignore"
}
```

즉, 실제 비밀번호나 DB 이름은 코드에 직접 쓰기보다 `.env` 파일에 작성하고 불러오는 방식으로 관리할 수 있다.

### 3.3 `pyproject.toml`

`pyproject.toml`은 Python 프로젝트의 기본 정보와 설치해야 하는 라이브러리를 적어두는 파일이다.

현재 프로젝트에는 다음 정보가 들어 있다.

- 프로젝트 이름: `ai-health-web-assignment`
- Python 버전: `>=3.13`
- 주요 의존성: FastAPI, SQLAlchemy, Alembic, asyncmy, pydantic-settings 등

의존성 예시는 다음과 같다.

```text
fastapi[standard]
sqlalchemy[asyncio]
alembic
asyncmy
pydantic-settings
```

쉽게 말하면 `pyproject.toml`은 프로젝트 설명서와 준비물 목록이다.

### 3.4 `uv.lock`

`uv.lock`은 설치되는 패키지의 정확한 버전을 기록하는 파일이다.

`pyproject.toml`이 준비물 목록이라면, `uv.lock`은 실제로 어떤 버전의 준비물을 설치했는지 적어둔 영수증과 같다.

이 파일이 있으면 팀원들이 같은 환경을 더 쉽게 맞출 수 있다.

예를 들어 한 사람은 FastAPI 0.135 버전을 쓰고, 다른 사람은 다른 버전을 쓰면 실행 결과가 달라질 수 있다.  
`uv.lock`은 이런 차이를 줄이는 역할을 한다.

## 4. 데이터베이스 연결 설정

데이터베이스 연결 설정은 `app/core/db/databases.py`에서 관리한다.

현재 프로젝트의 흐름은 다음과 같다.

```text
config.py에서 DB 설정값 읽기
→ databases.py에서 DATABASE_URL 만들기
→ create_async_engine으로 DB 엔진 생성
→ async_sessionmaker로 DB 세션 생성
→ API나 repository에서 세션 사용
```

### 4.1 DB 주소 만들기

현재 프로젝트는 MySQL 비동기 드라이버인 `asyncmy`를 사용한다.

```python
DATABASE_PREFIX = "mysql+asyncmy://"
DATABASE_URI = f"{settings.DB_USER}:{settings.DB_PASSWORD}@{settings.DB_HOST}:{settings.DB_PORT}/{settings.DB_NAME}"
DATABASE_URL = f"{DATABASE_PREFIX}{DATABASE_URI}"
```

예를 들어 설정값이 다음과 같다면:

```text
DB_USER=root
DB_PASSWORD=password1234
DB_HOST=localhost
DB_PORT=3306
DB_NAME=ai_health
```

DB 접속 주소는 다음과 같은 형태가 된다.

```text
mysql+asyncmy://root:password1234@localhost:3306/ai_health
```

### 4.2 비동기 엔진 생성

```python
async_engine = create_async_engine(DATABASE_URL, echo=False, future=True)
```

이 코드는 FastAPI가 데이터베이스에 비동기 방식으로 접속할 수 있도록 엔진을 만든다.

### 4.3 DB 세션 생성

```python
AsyncSessionLocal = async_sessionmaker(
    bind=async_engine,
    autoflush=False,
    expire_on_commit=False
)
```

세션은 데이터베이스와 대화하는 통로이다.  
데이터 조회, 저장, 수정, 삭제 작업을 할 때 세션을 사용한다.

### 4.4 FastAPI에서 사용할 DB 의존성

```python
async def async_get_db():
    async with AsyncSessionLocal() as db:
        yield db
```

이 함수는 API에서 DB 세션이 필요할 때 사용할 수 있다.

## 5. SQLAlchemy 모델 작성과 Alembic 마이그레이션 방법

### 5.1 SQLAlchemy 모델이란?

SQLAlchemy 모델은 데이터베이스 테이블을 Python 클래스로 표현한 것이다.

예를 들어 회원 테이블을 만들고 싶다면 다음과 같은 모델을 작성할 수 있다.

```python
from sqlalchemy import Integer, String
from sqlalchemy.orm import Mapped, mapped_column

from app.core.db.databases import Base


class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    name: Mapped[str] = mapped_column(String(10), nullable=False)
    age: Mapped[int] = mapped_column(Integer, nullable=False)
    email: Mapped[str] = mapped_column(String(30), unique=True, nullable=False)
    password: Mapped[str] = mapped_column(String(20), nullable=False)
```

이 코드는 `users`라는 테이블을 만들기 위한 설계도이다.

### 5.2 모델 작성 위치

모델 파일은 보통 `app/models/` 안에 작성한다.

예시:

```text
app/models/user.py
```

그리고 Alembic이 모델을 찾을 수 있도록 `app/models/__init__.py`에서 import한다.

```python
from app.models.user import User
```

### 5.3 Alembic이란?

Alembic은 SQLAlchemy 모델 변경 내용을 데이터베이스에 반영하는 도구이다.

쉽게 말하면:

```text
SQLAlchemy 모델 = 테이블 설계도
Alembic = 설계도를 보고 실제 DB 공사를 진행하는 도구
```

### 5.4 마이그레이션 수행 순서

1. SQLAlchemy 모델을 작성한다.
2. 모델을 `app/models/__init__.py`에서 import한다.
3. `.env` 파일에 DB 접속 정보를 작성한다.
4. 마이그레이션 파일을 생성한다.
5. 마이그레이션을 DB에 적용한다.

명령어는 다음과 같다.

```bash
uv run alembic revision --autogenerate -m "create users table"
```

위 명령어는 모델과 현재 DB 상태를 비교해서 마이그레이션 파일을 만든다.

그 다음 DB에 적용한다.

```bash
uv run alembic upgrade head
```

만약 직전 마이그레이션을 되돌리고 싶다면 다음 명령어를 사용한다.

```bash
uv run alembic downgrade -1
```

현재 사용자 컴퓨터에서 `uv` 명령어가 없다면, 가상환경 또는 설치 방식에 따라 다음처럼 실행할 수도 있다.

```bash
python3 -m alembic revision --autogenerate -m "create users table"
python3 -m alembic upgrade head
```

## 6. API 구현 흐름

FastAPI에서 API를 구현하는 흐름은 다음과 같다.

```text
1. schemas에서 요청/응답 데이터 모양 작성
2. models에서 DB 테이블 구조 작성
3. repositories에서 DB 조회/저장 함수 작성
4. services에서 실제 기능 로직 작성
5. apis에서 endpoint 작성
6. main.py에서 router 등록
7. 서버 실행 후 Swagger UI에서 테스트
```

예를 들어 회원 생성 API의 흐름은 다음과 같다.

```text
사용자가 POST /users 요청
→ API가 요청을 받음
→ Schema가 name, age, email, password 형식 검사
→ Service가 이메일 중복 여부 같은 규칙 검사
→ Repository가 DB에 회원 저장
→ DB 저장 결과를 응답 Schema에 맞게 반환
→ 사용자는 생성된 회원 정보를 받음
```

## 7. 이번 프로젝트에 적용해서 이해하기

이번 프로젝트에서 이미 작성되어 있는 구조를 기준으로 보면 다음과 같다.

| 위치 | 역할 |
| --- | --- |
| `app/main.py` | FastAPI 앱 생성, router 등록, static/media 파일 연결 |
| `app/core/config.py` | `.env` 기반 환경 설정 관리 |
| `app/core/db/databases.py` | MySQL 비동기 DB 연결 설정 |
| `app/core/db/models.py` | UUID, 생성일, 수정일, 삭제 여부 같은 공통 모델 mixin 관리 |
| `app/apis/` | API router 작성 위치 |
| `app/models/` | SQLAlchemy 테이블 모델 작성 위치 |
| `app/schemas/` | Pydantic 요청/응답 모델 작성 위치 |
| `app/services/` | 기능 처리 로직 작성 위치 |
| `app/repositories/` | DB 접근 로직 작성 위치 |
| `alembic/` | DB 마이그레이션 파일 관리 |
| `pyproject.toml` | 프로젝트 정보와 의존성 관리 |
| `uv.lock` | 의존성의 정확한 버전 고정 |

## 8. 정리

이 프로젝트는 FastAPI를 기반으로 API 서버를 만들기 위한 기본 구조를 가지고 있다.  
각 폴더는 역할이 나뉘어 있으며, API 요청이 들어오면 `apis → schemas/services → repositories → models/database` 흐름으로 처리된다.

데이터베이스는 `config.py`와 `.env`에서 설정값을 읽고, `databases.py`에서 SQLAlchemy 비동기 엔진과 세션을 만들어 연결한다.  
테이블 구조는 SQLAlchemy 모델로 작성하고, 실제 데이터베이스 반영은 Alembic 마이그레이션으로 수행한다.

따라서 앞으로 기능을 추가할 때는 한 파일에 모든 코드를 작성하기보다, 역할에 맞게 `apis`, `schemas`, `services`, `repositories`, `models`로 나누어 작성하는 것이 유지보수에 좋다.
