# 7일차 앱 실행화면

`main`에 merge된 백엔드(User/환자/진료기록/AI예측 API)를 기준으로, `./static` 프론트엔드 템플릿을 실제로 연결해서 각 화면이 정상 동작하는지 확인한 기록입니다.

## 실행 방법

```bash
uv sync
alembic upgrade head   # PR #23의 "heatmap_url을 nullable로" 마이그레이션까지 포함해서 최신화 필요
fastapi run app/main.py
```
`http://0.0.0.0:8000/` 접속.

## 진행 중 발견하고 고친 문제

### 회원가입 시 부서/성별 값 불일치 (422 에러)

`static/templates/signup.html`의 `<select>` 값이 `developer`/`medical team`/`researcher`, `male`/`female`로 되어 있는데, 백엔드 `DepartmentEnum`/`GenderEnum`은 `DEV`/`MEDICAL`/`RESEARCH`, `M`/`F`를 기대합니다. 실제로 원래 값 그대로 가입을 시도하면 아래처럼 실패합니다.

> 가입 실패 — Input should be 'MEDICAL', 'DEV' or 'RESEARCH', Input should be 'M' or 'F'

`signup.html`의 `<option value="...">` 값을 백엔드 Enum과 동일하게(`DEV`/`MEDICAL`/`RESEARCH`, `M`/`F`) 수정해서 해결했습니다. (동일한 문제를 팀원 moyajong님도 PR #25에서 독립적으로 발견·수정하셨습니다 — 환자 성별(`male`/`female`)은 백엔드가 이미 변환 처리하고 있어 그대로 둡니다.)

## Endpoint별 동작 확인

| Endpoint | 화면 | 확인 결과 |
| --- | --- | --- |
| `POST /api/v1/users/signup` | 회원가입 | 부서/성별 값 수정 후 "회원가입이 완료되었습니다" 알림과 함께 성공 |
| `POST /api/v1/users/login` | 로그인 | 로그인 성공 시 환자 목록 페이지로 자동 이동, 헤더에 로그인한 사용자명(부서) 표시 |
| `GET /api/v1/patients` | 환자 목록 | 등록된 환자가 ID/이름/나이/성별/전화번호 컬럼으로 정상 표시 |
| `GET /api/v1/patients/{id}` | 환자 상세 | 이름/성별/나이/연락처 정상 표시, 그 환자의 진료기록 목록도 같이 표시 |
| `GET /api/v1/patients/{id}/medical-records` | 진료기록 목록(환자 상세 내) | 차트번호/증상/등록일 정상 표시 |
| `GET /api/v1/medical-records/{id}` | 진료기록 상세 | 차트번호/증상/등록일 + 업로드된 실제 X-Ray 이미지 정상 렌더링 |
| `POST /api/v1/medical-records/{record_id}/predict` | AI 예측 결과보기 버튼 | 클릭 시 "AI 예측이 완료되었습니다" 알림, 결과 테이블에 수행일시/폐렴여부(Positive)/Confidence(96.04%)/사용모델 표시 |
| `GET /api/v1/medical-records/{record_id}/analyses` | AI 예측 결과 목록(같은 페이지) | 예측을 여러 번(다른 모델 이름으로) 수행한 이력이 테이블에 누적 표시됨 |
